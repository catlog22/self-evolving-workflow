# Swarm coordination through Maestro MCP

Use the active v3 Run ID as `session_id` for `team_agent`, `team_task` and `team_msg`. Keep the canonical Session ID for Run CLI calls. Bind the MCP server to the Run's repository so workers can open the same Skill revision and write their assigned outputs.

1. Initialize the usual `team-session.json` and ACO configuration under the exact Run. Use `team_task.create` to record each assignment and `update` to move it through `assigned` and `in_progress`. Store the mapping from ant ID to returned task ID.
2. Call `team_agent.spawn_agent` for each assignment. Set `role` to the unique assignment ID, select the configured worker CLI with `tool`, and use `mode: "write"` for a worker that must save an artifact. Include the canonical Session and Run IDs, role links, exact output path and task ID in the prompt. The Codex worker starts with the `maestro_run` MCP connection. It uses `run_skill_read` to open `SKILL.md` and the links for its role before executing it. Workers with shell access can use `maestro run skill-read`.
3. After saving and re-reading its artifact, the worker reports `task_complete` via `team_msg.log` to `coordinator` with the assignment ID, iteration, task ID and artifact path. Set `delivery_method: "poll"`. A worker without the MCP tool can use `maestro agent-msg send <summary> --session <run-id> --from <assignment-id> --to coordinator --type task_complete --delivery-method poll --data '<json-object>'`.
4. Keep the host open during worker execution. Call `team_agent.wait` with the current roles and repeat bounded calls while jobs are active. Read `team_agent.members` for job state after reconnecting. Verify the callback against the member role and iteration, task ID and readable artifact. Move validated tasks through `pending_review` to `done`. Apply the controller update when every assignment for this iteration is accounted for. Report a failed worker through the existing blocker and retry flow. Keep the prior attempt in the Run evidence, and use a new unique member role for a new attempt.
5. For `scoring.mode: "llm"`, dispatch `SCORE-<k>` only after accepting the ant artifacts. The scorer opens its role and score schema, writes `work/team/scores/iter-<k>-scores.json`, and sends `scoring_complete` with the iteration and scores path. Wait for the member, then verify the callback and score coverage. The controller checks the score file before committing. If the scorer fails, record the decision to retry or call `update --allow-score-fallback` for that iteration.
6. After reconnecting, use `run brief`, then read the persisted roster, `team_task.list`, coordinator state and `team_msg.list` for the current iteration. The message history includes acknowledged callbacks. Re-run `select --iter <k>` for the saved assignments. Use `read_mailbox` for pending delivery, and use the controller's committed iteration state to decide whether to replay the update with its original scoring choice. Keep active worker jobs attached to their existing assignments. Resume synthesis with the same roster, callback and artifact checks.
